# MSCPHUB -- MSCP-сервер дисков для узлов OpenVMS

MSCPHUB работает под Linux. Он даёт узлам OpenVMS в той же локальной
сети пользоваться файлами и блочными устройствами Linux как своими
дисками. Для узла OpenVMS он -- контроллер дисков кластера, вроде HSC:
узел видит его диски в SHOW DEVICE и монтирует их командой MOUNT.
Один диск могут смонтировать несколько узлов: MOUNT/CLUSTER.

MSCPHUB говорит по Ethernet на NISCA -- протоколе PEDRIVER. Он не
член VMScluster и не имеет голосов. На узлах OpenVMS ничего менять не
нужно.

На WRITE сервер отвечает только тогда, когда данные уже на диске
Linux-машины: OpenVMS никогда не просит диск сбросить свой кэш.

Формат:

```
mscphub /CONFIG=file-spec
mscphub /INTERFACE=name /NODE=name /SYSTEMID=n /GROUP=n /AUTHORIZE=hex [/qualifier...]
mscphub /HELP[="topic..."]
```

Квалификатор задаётся в командной строке или, по одному в строке, в
файле /CONFIG. Вместо /ИМЯ=значение можно писать --ИМЯ=значение.
Квалификатор, которого сервер не знает, пропускается с
предупреждением.

Руководства: "Руководство пользователя MSCPHUB"
(mscphub_users_guide_ru.md) и "Руководство программиста MSCPHUB"
(mscphub_programmers_guide_ru.md) в /opt/mscphub/share/doc/mscphub;
страница руководства mscphub(8).

## /ACK -- когда сервер подтверждает отдельно

```
/ACK=HOLD | FLUSH     (default HOLD)
```

Задаёт, когда сервер подтверждает пакеты узла отдельным пакетом.
Обычно подтверждение едет в пакете сервера -- в ответе на команду, в
данных READ. Когда серверу нечего послать, он шлёт подтверждение
отдельно.

- HOLD -- отдельно, только когда узел просит подтвердить сразу, после
  4 пакетов или самое позднее через 20 мс; в остальных случаях
  подтверждение ждёт ответа сервера.
- FLUSH -- отдельно, как только сервер забрал все пришедшие кадры.

По умолчанию -- /ACK=HOLD. HOLD шлёт намного меньше пакетов; сравнить
режимы помогут сообщения ACKSTATS и LATSTATS.

## /ALLOCLASS -- allocation class дисков

```
/ALLOCLASS=n     (default 0)
```

Задаёт allocation class сервера, 0-255. При /ALLOCLASS=42 узлы
OpenVMS называют диск DKA100 сервера $42$DKA100, при 0 -- MHUB$DKA100,
по SCSNODE сервера. По умолчанию -- 0.

Не меняйте его, пока узлы OpenVMS пользуются дисками. Не давайте
класс, который кластер уже даёт дискам с теми же именами.

## /AUTHORIZE -- пароль кластера

```
/AUTHORIZE=hex
```

Задаёт пароль кластера в виде 8-байтового хэша, который OpenVMS
хранит в SYS$SYSTEM:CLUSTER_AUTHORIZE.DAT: 16 шестнадцатеричных цифр,
байты начиная с младшего. Обязателен. Чтобы его узнать, выведите
файл на узле OpenVMS:

```
$ DUMP SYS$SYSTEM:CLUSTER_AUTHORIZE.DAT
```

Хэш -- квадрослово по смещению 8. Длинные слова 00000000 8EF54F24 в
этом месте дают /AUTHORIZE=5A3C9E1700000000.

## /CONFIG -- взять квалификаторы из файла

```
/CONFIG=file-spec
```

Читает квалификаторы из указанного файла, по одному в строке, как в
командной строке. Строка, начинающаяся с !, -- комментарий.
Квалификаторы командной строки тоже учитываются.

```
! MSCPHUB of our cluster
/INTERFACE=mh0
/NODE=MHUB
/SYSTEMID=65200
/GROUP=4242
/AUTHORIZE=5A3C9E1700000000
```

## /CREDITS -- сколько команд узел может прислать сразу

```
/CREDITS=n     (default 16)
```

Задаёт, сколько команд каждый узел OpenVMS может одновременно держать
в работе у дискового сервера, 2-64. Число выдаётся узлу при
подключении. По умолчанию -- 16.

## /GROUP -- номер группы кластера

```
/GROUP=n
```

Задаёт номер группы кластера узлов OpenVMS, 1-65279. Обязателен. На
OpenVMS его показывает MCR SYSMAN CONFIGURATION SHOW
CLUSTER_AUTHORIZATION.

## /HELP -- показать это описание

```
/HELP
/HELP="topic subtopic"
```

Показывает библиотеку помощи сервера -- всё описание или названную
тему -- и завершает работу.

```
$ mscphub /HELP=/SYSTEMID
$ mscphub "/HELP=Messages IDCLASH"
```

## /INTERFACE -- сетевой интерфейс

```
/INTERFACE=name
```

Задаёт интерфейс Linux, в сети которого узлы OpenVMS: адаптер
Ethernet, мост, VLAN, tap-устройство в мосту. Обязателен. Серверу
нужны права CAP_NET_RAW: запускайте его от root. MAC-адрес интерфейса
не меняется.

## /LISTEN -- секунды тишины при старте

```
/LISTEN=seconds     (default 4)
```

Задаёт, сколько сервер слушает сеть, прежде чем что-то послать, 1-60
секунд. За это время он узнаёт узлы сети по их сообщениям HELLO. Если
какой-то узел использует имя или системный номер сервера, сервер
останавливается. По умолчанию -- 4.

## /LOGFILE -- файл журнала

```
/LOGFILE=file-spec
```

Пишет сообщения в указанный файл. По умолчанию они идут в
стандартный поток ошибок, который systemd хранит в своём журнале;
скрипты OpenRC и System V init направляют его в /var/log/mscphub.log.

## /MODBUS -- отдавать счётчики по Modbus/TCP

```
/MODBUS=[address:]port
```

Задаёт порт TCP и адрес, на которых сервер отвечает на запросы
Modbus/TCP о своих счётчиках: их может читать SCADA, панель ПЛК или
любой клиент Modbus. Порт Modbus — 502, годится и любой другой. Без
/MODBUS ничего не отдаётся.

Счётчики отдаёт отдельная нить из копии, которую сервер делает каждые
100 мс; клиент никогда не задерживает диски. Регистры читаются
функциями 03 и 04, сведения об устройстве — функцией 2B/0E; писать
нельзя ничего. Карта регистров — в Руководстве пользователя,
приложение D.

```
/MODBUS=502
/MODBUS=192.168.1.10:1502
```

## /NODE -- SCSNODE сервера

```
/NODE=name
```

Задаёт SCSNODE сервера: 1-6 символов A-Z, 0-9, $ и _. Обязателен. Не
должен совпадать с именем другого узла группы.

## /PASSIVE -- ничего не передавать

```
/PASSIVE
```

Сервер только слушает и сообщает об увиденных узлах. Каналов не
открывает и ничего не передаёт. Безопасно в любой сети, например
чтобы посмотреть на рабочий кластер.

## /SYNC -- когда WRITE считается записанным

```
/SYNC=DSYNC | GROUP | NONE     (default DSYNC)
```

Задаёт, как WRITE доводится до диска, прежде чем на него ответить.

- DSYNC -- каждая запись идёт на носитель сама по себе.
- GROUP -- записи, закончившиеся, пока диск сбрасывает кэш, ждут
  следующего сброса и получают ответ вместе: сбросов меньше, когда
  пишут сразу много узлов. Так же надёжно, как DSYNC.
- NONE -- то же, что /UNSAFE.

По умолчанию -- /SYNC=DSYNC.

## /SYSTEMID -- SCSSYSTEMID сервера

```
/SYSTEMID=n
```

Задаёт SCSSYSTEMID сервера, 1-65535. Обязателен. Должен отличаться от
SCSSYSTEMID всех других узлов группы: в сети узлы различаются только
по младшим 16 битам SCSSYSTEMID. На OpenVMS занятые номера покажут MCR
SYSGEN SHOW SCSSYSTEMID и SHOW CLUSTER.

## /TIMEZONE -- часовой пояс времени для узлов

```
/TIMEZONE=LOCAL | UTC | [+|-]hh[:mm]     (default LOCAL)
```

Задаёт часовой пояс времени, которое сервер сообщает узлам, когда
открывает виртуальный канал. SHOW CLUSTER и SCACP показывают его как
время запуска сервера. LOCAL -- пояс Linux-машины, вместе с летним
временем. По умолчанию -- LOCAL. Это время видит только оператор;
протокол работает с любым поясом.

## /TRACE -- писать в журнал каждый кадр

```
/TRACE
```

Пишет в журнал каждый принятый кадр и каждый шаг каждого канала.
Включайте только ненадолго.

## /UNIT0 ... /UNIT7 -- диски

```
/UNIT0=name,path[,RO][,MEDIA=medium][,SECTOR=octets]
```

Задаёт диск. Имя -- DKcn: буква контроллера A-Z и номер 0-9999,
например DKA100. Путь -- это:

- файл Linux. Его размер при старте в блоках по 512 байт -- размер
  диска. Сервер забирает файл себе блокировкой: второй сервер
  раздавать его не сможет. Файл читается и пишется прямым
  вводом-выводом, если файловая система это позволяет, иначе через
  страничный кэш (NODIRECT).
- блочное устройство: диск, раздел, том LVM, loop-устройство, LUN
  iSCSI. Сервер открывает его для монопольного использования:
  устройство, смонтированное на Linux-машине или занятое другим
  сервером, он не возьмёт (DEVBUSY). О разделе, который начинается не
  на границе физического сектора, сервер предупреждает (MISALIGN).

Параметры, в любом порядке:

- RO -- только чтение. Узел монтирует диск с защитой от записи.
- MEDIA=medium -- кем диск представляется узлу: две или три буквы и
  число. По умолчанию -- RZ29, а с RO -- RRD42.
- SECTOR=octets -- считать файл диском с сектором 512, 1024, 2048 или
  4096 байт. Только для проверки 4K-дисков; блочное устройство само
  сообщает свой сектор.

Устройство с сектором 4096 байт работает: запись не целыми секторами
идёт как чтение-изменение-запись. OpenVMS пишет блоками по 512 байт.
Чтобы большая часть её записей шла целыми секторами, инициализируйте
диск с кластером 8 или кратным 8: INITIALIZE/CLUSTER=16 $42$DKA100:
DATA1. На диске больше 50000 блоков OpenVMS так делает сама, на
меньшем берёт 1.

Примеры:

```
/ALLOCLASS=42
/UNIT0=DKA100,/srv/vms/data1.img
/UNIT1=DKA200,/dev/vg0/vmsdata
/UNIT2=DKA300,/srv/iso/axpvms083.iso,RO
```

## /UNSAFE -- отвечать на WRITE до записи на диск

```
/UNSAFE
```

Отвечает на WRITE, как только Linux принял данные, ещё до того, как
они на диске. Так быстрее, но при сбое или пропадании питания
Linux-машины пропадут данные, которые узел OpenVMS считает
записанными. Только для испытаний. При старте сервер выводит UNSAFE.

## MHMON -- монитор сервера

```
mhmon [DISK | NODES | SERVER | ALL] [/qualifier...]
```

MHMON показывает, что делает работающий сервер, как утилита MONITOR
в OpenVMS: каждые /INTERVAL секунд — значение за последний интервал
(CUR), а также среднее, наименьшее и наибольшее с запуска MHMON (AVE,
MIN, MAX). Он читает копию счётчиков, которую сервер каждые 100 мс
делает в общей памяти (/dev/shm/mscphub.<узел>), и никогда в неё не
пишет. С /RECORD он пишет счётчики в файл в стиле T4 для TLViz и
других средств T4.

Запускать от root на компьютере сервера.

```
# mhmon
# mhmon NODES
# mhmon DISK /ITEM=ALL /INTERVAL=5
# mhmon ALL /NODISPLAY /RECORD=/var/opt/mscphub/t4 /INTERVAL=60
```

### Classes

- DISK -- каждый диск: его имя на узлах, метка тома, узлы, у которых
  он в состоянии online (смонтирован или монтируется), и величина из
  /ITEM. По умолчанию.
- NODES -- каждый узел, который знает сервер: его системный номер,
  состояние канала и виртуального канала, сколько раз открывался
  канал, его соединения, диски, которые у него online, и команды MSCP
  в секунду.
- SERVER -- кадры, килобайты, повторные передачи, дубликаты и пакеты
  не по порядку, отданные и принятые данные, команды в работе, занятые
  буферы данных.
- ALL -- все три по очереди, по одному за интервал.

### /ENDING

```
/ENDING=hh:mm[:ss]
```

Задаёт, когда MHMON остановится: сегодня или завтра, если время уже
прошло. Без него MHMON работает до Ctrl/C или SIGTERM.

### /INTERVAL

```
/INTERVAL=seconds     (default 3)
```

Задаёт число секунд между замерами, от 1 до 3600. Замеры приходятся
на границы интервала по часам: с /INTERVAL=60 — на начало минуты.

### /ITEM

```
/ITEM=OPERATION_RATE | THROUGHPUT | QUEUE_LENGTH | RESPONSE_TIME | ALL
```

Задаёт, что показывает класс DISK: команды в секунду, килобайты в
секунду, среднее число команд в работе и в очереди, среднее время от
команды до ответа в миллисекундах; ALL показывает их по очереди. По
умолчанию — OPERATION_RATE.

### /NODE

```
/NODE=name
```

Задаёт SCSNODE сервера, за которым смотреть, если на компьютере их
несколько. Без него MHMON берёт единственный.

### /NODISPLAY

```
/NODISPLAY
```

Ничего не показывать, только записывать. Нужен /RECORD.

### /RECORD

```
/RECORD=file-spec | directory
```

Пишет значения каждого интервала в файл в стиле T4: узел, дата и
время начала, имена столбцов, затем по строке на замер — время конца
замера и значения. Поле без значения пустое; число полей во всех
строках одинаково. Столбцы — те, что были у сервера, когда файл
начат: его строки, четыре величины каждого диска, команды каждого
узла.

В каталоге заводится по файлу в день,
T4_<узел>_<дата>_<начало>_<конец>.CSV, как у файлов T4; файл, который
сейчас пишется, кончается на _RUN. Запись ждёт сервер, который ещё не
запущен, и продолжается, когда он возвращается.

### T4 -- запись постоянно

Служба mscphub-t4.service каждую минуту пишет счётчики в
/var/opt/mscphub/t4, по файлу в день. Она устанавливается, но не
включается:

```
# systemctl enable --now mscphub-t4
```

## Signals -- сигналы

```
SIGINT, SIGTERM    stop the server (SHUTDOWN)
SIGUSR1            write the state and the counters to the log: UPTIME,
                   a NODESTATS for each node, STATS, TRSTATS, ACKSTATS,
                   BLKSTATS, MSCPSTATS, then UNITSTATS, BKSTATS and
                   LATSTATS for each disk
```

Под systemd:

```
# systemctl kill -s USR1 mscphub
# journalctl -u mscphub -n 40
```

Счётчики идут с запуска сервера. Чтобы измерить тест, пошлите
SIGUSR1 до и после него и вычтите.

## Service -- сервер как служба systemd

Установка кладёт юнит mscphub.service, но не включает его: сервер,
запущенный сам по себе, сразу начинает разговаривать с кластером в
своей сети. Юнит читает /etc/opt/mscphub/mscphub.conf и без него не
запускается.

```
# cp /etc/opt/mscphub/mscphub.conf.example /etc/opt/mscphub/mscphub.conf
# vi /etc/opt/mscphub/mscphub.conf
# systemctl enable --now mscphub
# journalctl -u mscphub -f
```

Чтобы привязать сервер к процессору или изменить его строку запуска,
используйте drop-in (systemctl edit mscphub); сам юнит не правьте.

Без systemd установка кладёт вместо юнита скрипт OpenRC или System V
init в /etc/init.d, тоже не включённый; его журнал --
/var/log/mscphub.log:

```
# rc-update add mscphub default         OpenRC
# rc-service mscphub start
# rc-service mscphub report             SIGUSR1

# update-rc.d mscphub defaults          System V init
# /etc/init.d/mscphub start
# /etc/init.d/mscphub report            SIGUSR1
```

Его переменные -- файл параметров, журнал, процессоры -- задаются в
/etc/conf.d/mscphub (OpenRC) или /etc/default/mscphub (System V).

## Troubleshooting -- что проверить первым делом

Сервер сразу останавливается. Последнее сообщение -- с важностью F,
и в нём сказана причина. См. тему Messages.

Не видно ни одного узла: ANNOUNCE сообщает 0 других узлов. Проверьте
/GROUP. Проверьте, что интерфейс поднят и стоит в нужном мосту или
VLAN. На OpenVMS проверьте, что PEDRIVER работает: MCR SCACP SHOW
CHANNEL. Посмотрите на провод:

```
# tcpdump -i eth1 ether proto 0x6007
```

Узлы видны, но CHOPEN нет. Поищите AUTHFAIL: хэш в /AUTHORIZE не тот,
что у группы. Проверьте, что не задан /PASSIVE.

Канал открывается и снова закрывается, раз за разом. Причина
написана в CHCLOSE. "nothing heard from the node" значит, что кадры
теряются между узлом и сервером: проверьте коммутатор, мост, VLAN.

Канал открыт, но VCOPEN нет. Запустите ненадолго сервер с /TRACE и
поищите "PPD START" и предупреждение после него.

Виртуальный канал открыт, но дисков на узле нет. Поищите CONOPEN. Нет
CONOPEN -- проверьте, что заданы /UNITn (UNITCFG при старте). На
OpenVMS проверьте, что работает процесс CONFIGURE (SHOW SYSTEM).

Виртуальный канал раз за разом закрывается, или запись идёт медленно,
а чтение нет. Причина написана в VCCLOSE; посмотрите и TRSTATS: много
повторов значит, что теряются кадры к узлам, много "out of order" --
что теряются кадры от узлов.

MOUNT или COPY на узле кончается ошибкой ввода-вывода. Поищите IOERR,
IOSTUCK, MSCPERR и BLKERR.

Диски работают медленно. Поищите NODIRECT и MISALIGN. Разрежённый
образ медленный, пока его не запишут один раз; заполните его
целиком с помощью dd. LATSTATS показывает, на что уходит время
команды.

## Messages -- сообщения сервера

Каждое сообщение имеет форму OpenVMS:

```
%MSCPHUB-F-IDCLASH, node ALPHA1 (08-00-2B-E5-40-01) uses the system ID low word 65534 of this server
```

Буква после MSCPHUB -- важность: S успех, I информация, W
предупреждение, E ошибка, F фатальная (сервер останавливается). В
текстах ниже слово в кавычках обозначает значение, которое
подставляет сервер.

### ACKSTATS

```
acknowledgements (/ACK='mode'): 'n' asked for at once; 'n' with a packet of ours, 'n' alone: 'n' asked, 'n' for a duplicate, 'n' for 'n' packets, 'n' when drained, 'n' on the tick
```

Важность: информационное.

Пояснение: Пишется по SIGUSR1 после TRSTATS. Сколько пакетов узлов
просили подтвердить сразу, сколько подтверждений уехало в пакете
сервера и сколько ушло отдельно -- по просьбе узла, на пакет,
пришедший дважды, на пачку пакетов (/ACK=HOLD), когда все кадры
забраны (/ACK=FLUSH), или по такту 20 мс. Чем меньше отдельных, тем
лучше.

Действия пользователя: Не нужны.

### ANNOUNCE

```
node 'name' 'state' on 'interface', 'n' other node(s) seen in group 'n'
```

Важность: информационное.

Пояснение: Время тишины вышло, и сервер теперь шлёт сообщения HELLO.
С /PASSIVE сказано "listens only", и сервер ничего не шлёт.

Действия пользователя: Не нужны. Если не видно ни одного другого
узла, см. Troubleshooting.

### AUTHFAIL

```
node 'name' ('systemid', 'adapter') sent a CC message with a wrong cluster password, ignored
```

Важность: предупреждение.

Пояснение: Узел в группе сервера, но хэш его пароля не совпадает с
/AUTHORIZE. Канал к узлу не открывается. Сообщение пишется по одному
разу на узел.

Действия пользователя: Задайте в /AUTHORIZE хэш кластера этого узла
(см. /AUTHORIZE) и проверьте /GROUP.

### BKSTATS

```
unit 'name': sector 'n', 'n' read-modify-write(s) needing 'n' sector(s), 'n' from the cache (in the last 2/16/128/512 written: 'n'/'n'/'n'/'n'), 'n' wait(s) for a range, 'n' group fdatasync(s) for 'n' write(s), 'n' ZERO(s) ('n' as zeros written)
```

Важность: информационное.

Пояснение: Пишется по SIGUSR1 для каждого диска после его UNITSTATS:
сектор диска; сколько записей прошло как чтение-изменение-запись
(диск с сектором 4096 байт) и сколько секторов им сначала
понадобилось; сколько из них взято из кэша 128 последних записанных
секторов; сколько было среди последних 2, 16, 128 и 512 записанных;
сколько записей ждали другую запись в те же секторы; при
/SYNC=GROUP -- сколько сбросов кэша покрыли сколько записей; сколько
пришло команд ERASE и сколько из них сделано записью нулей.

Действия пользователя: Не нужны.

### BLKERR

```
'operation' from 'name' ('systemid'), XCT_ID 'id': 'reason', dropped
```

Важность: предупреждение.

Пояснение: От узла пришёл кусок данных, которого не ждёт ни одна
команда сервера: команда уже кончилась или узел прислал кусок
дважды. Сервер его отбрасывает. Ни одной из сторон это не вредит.

Действия пользователя: Не нужны, если это редко. Если часто --
сообщите, приложив журнал с /TRACE.

### BLKSTATS

```
block transfers: 'n' chunk(s) sent ('n' octets), 'n' RET_CNF, 'n' REQ_DAT, 'n' chunk(s) taken ('n' octets), 'n' dropped
```

Важность: информационное.

Пояснение: Пишется по SIGUSR1 после ACKSTATS: куски данных,
отправленные узлам (READ), и сколько в них байт, подтверждения,
которые узлы прислали на них, запросы данных, отправленные сервером
(WRITE), принятые куски и сколько в них байт, отброшенные куски.

Действия пользователя: Не нужны.

### CHCLOSE

```
channel to node 'name' ('systemid') is closed: 'reason'
```

Важность: предупреждение.

Пояснение: Канал к узлу закрыт. Причина -- одна из:

```
BYE received, the node is going down     the node shuts down or crashes
restarted by the node                    the node started a new channel
no answer to the handshake in 5 seconds
nothing heard from the node for 8 seconds
the node has changed its name or system ID
the server is stopping
```

Работающий узел снова откроет канал через несколько секунд.

Действия пользователя: Не нужны, если канал открылся снова. Если нет
или если он закрывается раз за разом, см. Troubleshooting.

### CHOPEN

```
channel to node 'name' ('systemid') is open, CC V1.'n', pipe quota 'n', buffer 'n', services 'xxxx'/'xxxx'
```

Важность: информационное.

Пояснение: Рукопожатие с узлом закончено. Показаны версия узла, его
pipe quota, размер буфера и сервисы (предлагает/требует).

Действия пользователя: Не нужны.

### CONCLOSE

```
connection 'name' of 'node' ('systemid') is closed: 'reason'
```

Важность: информационное.

Пояснение: Соединение с дисковым сервером закрыто: узел отключился,
его виртуальный канал закрылся или сервер разорвал соединение сам.

Действия пользователя: Не нужны; узел соединится снова. Если причина
-- "an end message was held back", см. MSCPERR.

### CONOPEN

```
connection 'name' of 'node' ('systemid') to 'server' is open, credit 'n'/'n'
```

Важность: информационное.

Пояснение: Узел OpenVMS соединился с дисковым сервером MSCP$DISK:
это его драйвер класса дисков, VMS$DISK_CL_DRVR. Показаны кредиты
обеих сторон. Теперь диски сервера появляются на узле.

Действия пользователя: Не нужны.

### DEVBUSY

```
the device 'device' is in use: mounted on this host, or another server has it
```

Важность: фатальное.

Пояснение: Сервер не может забрать себе блочное устройство из
/UNITn: оно смонтировано на Linux-машине, занято LVM или RAID или его
держит другой сервер. Сервер останавливается.

Действия пользователя: Отмонтируйте устройство или дайте другое.
Никогда не раздавайте устройство, которым пользуется сама
Linux-машина.

### IDCLASH

```
node 'name' ('adapter') uses the system ID low word 'n' of this server
```

Важность: фатальное.

Пояснение: Другой узел использует те же младшие 16 бит SCSSYSTEMID,
что и сервер. Такие узлы в сети не различить. Сервер
останавливается, ничего не передав.

Действия пользователя: Дайте серверу другой /SYSTEMID. На OpenVMS
занятые номера покажут SHOW CLUSTER или MCR SYSGEN SHOW SCSSYSTEMID.

### IOERR

```
'operation' of unit 'name', LBN 'n', 'n' octets, failed: errno='n' ('text')
```

Важность: ошибка.

Пояснение: Файл или устройство Linux под диском не удалось прочитать
или записать. В сообщении команда, диск, блок, размер и ошибка
Linux. Узел OpenVMS получает ошибку привода.

Действия пользователя: Проверьте файловую систему и диск
Linux-машины. "No space left on device" значит, что файл
разрежённый, а его файловая система заполнена.

### IOSTUCK

```
'operation' of unit 'name', LBN 'n', is in the backend for 'n' seconds: cancelled
```

Важность: предупреждение.

Пояснение: Команда уже 15 секунд в диске Linux. Сервер отменяет её;
если отмена прошла, узел получает ошибку привода. Если нет (Linux ещё
пишет), диск её ждёт.

Действия пользователя: Проверьте диск Linux под юнитом: умерший
диск, пропавший сервер iSCSI или NFS. Смотрите dmesg.

### IVPARAM

```
illegal value 'value' of /'name': 'what is expected'
```

Важность: фатальное.

Пояснение: У квалификатора неверное значение. В сообщении сказано,
какое ожидается. Сервер останавливается.

Действия пользователя: Исправьте значение.

### LATSTATS

```
unit 'name', 'operation': 'n' command(s), average 'n' us (backend 'n', transfers 'n', the rest 'n'), longest 'n' us; under 0.1/0.3/1/3/10 ms and longer: 'n'/'n'/'n'/'n'/'n'/'n'
```

Важность: информационное.

Пояснение: Пишется по SIGUSR1 для каждого диска и для каждой из
команд READ и WRITE, после его BKSTATS, если такие команды были.
Среднее время от команды до ответа в микросекундах и на что оно
ушло: диск Linux (backend), данные по сети (transfers) и остальное --
ожидание диска, сам сервер. Дальше самое долгое время и сколько
команд заняли меньше 0,1, 0,3, 1, 3 и 10 мс и дольше.

Действия пользователя: Не нужны.

### LISTEN

```
listening 'n' second(s) before announcing the node
```

Важность: информационное.

Пояснение: Сервер слушает сеть /LISTEN секунд, прежде чем что-то
послать.

Действия пользователя: Не нужны.

### MANYNODES

```
more than 'n' nodes on the LAN, node 'name' is not remembered
```

Важность: предупреждение.

Пояснение: Узлов в сети больше, чем помнит сервер (64). Лишний узел
на совпадение не проверяется.

Действия пользователя: Сообщите об этом.

### MANYSERVERS

```
'n' MSCPHUB servers run on this host: give /NODE
```

Важность: ошибка.

Пояснение: MHMON нашёл на компьютере статистику нескольких серверов и
не знает, какой показывать.

Действия пользователя: Укажите MHMON SCSNODE сервера: /NODE=имя.

### MBUSERR

```
the counters are not served over Modbus/TCP: 'call' failed, errno='n' ('text')
```

Важность: предупреждение.

Пояснение: /MODBUS задан, но сервер не может там отдавать счётчики:
чаще всего порт занят другой программой (bind, errno=98) или адрес не
принадлежит этому компьютеру (bind, errno=99). Диски сервер
обслуживает и без этого.

Действия пользователя: Задайте в /MODBUS другой порт или адрес либо
остановите программу, занявшую порт.

### MISALIGN

```
'device' starts 'n' octets into a physical sector of 'n': every write is a read-modify-write of the disk
```

Важность: предупреждение.

Пояснение: Блочное устройство из /UNITn -- чаще всего раздел --
начинается не на границе физического сектора диска Linux. Тогда ни
одна запись узла не ложится целыми секторами, и каждая идёт как
чтение-изменение-запись. Сервер всё равно раздаёт устройство.

Действия пользователя: Для нового диска сделайте раздел с началом,
кратным 1 МБ (parted и fdisk так делают по умолчанию), и перенесите
данные.

### MODBUS

```
the counters are served over Modbus/TCP on 'address', port 'n'
```

Важность: информационное.

Пояснение: Сервер отвечает на запросы Modbus/TCP о своих счётчиках
(/MODBUS).

Действия пользователя: Не требуются.

### MSCPERR

```
end message of 'operation' to 'connection' of 'node' ('systemid') held back: 'reason'
```

Важность: ошибка.

Пояснение: Сервер собирался отправить ответ, от которого узел OpenVMS
упал бы. Он его не отправил и разорвал соединение. Это ошибка
сервера.

Действия пользователя: Сообщите о ней, приложив журнал /TRACE.

### MSCPSTATS

```
MSCP server: 'n' command(s) in progress, 'n' octets of data buffers in use
```

Важность: информационное.

Пояснение: Пишется по SIGUSR1 после BLKSTATS. Когда дисками никто не
пользуется, оба числа 0.

Действия пользователя: Не нужны. Если число остаётся больше 0, хотя
ни один узел не подключён, это ошибка сервера: сообщите о ней и
приложите журнал.

### NAMECLASH

```
node 'name' ('adapter', system ID 'n') uses the SCSNODE of this server
```

Важность: фатальное.

Пояснение: У другого узла тот же SCSNODE, что у сервера. Сервер
останавливается, ничего не передав.

Действия пользователя: Дайте серверу другой /NODE.

### NEWNODE

```
node 'name', system ID 'n', adapter 'adapter', CC V1.'n' ('n' octets)
```

Важность: информационное.

Пояснение: Сервер впервые увидел узел: его имя, системный номер,
адаптер и версию.

Действия пользователя: Не нужны.

### NODESTATS

```
node 'name' ('systemid'): channel 'state', open 'n' time(s); virtual circuit 'state', open 'n' time(s); 'n' connection(s) open
```

Важность: информационное.

Пояснение: Пишется по SIGUSR1 для каждого известного серверу узла,
после UPTIME. Дважды OPEN и одно соединение -- это узел, который
пользуется дисками. Растущее число открытий значит, что узел то
пропадает, то появляется.

Действия пользователя: Не нужны. Если счётчики растут, смотрите
CHCLOSE и VCCLOSE в журнале.

### NODIRECT

```
'path': no direct I/O ('reason'), served through the page cache
```

Важность: информационное.

Пояснение: Файловая система файла из /UNITn не позволяет прямой
ввод-вывод, или размер файла не кратен блоку в 512 байт. Сервер
раздаёт файл через страничный кэш: это работает, но каждая запись
обходится дороже.

Действия пользователя: Не нужны; для скорости положите образ на ext4
или XFS или раздавайте раздел либо том LVM.

### NOPARAM

```
the parameter /'name' is mandatory
```

Важность: фатальное.

Пояснение: Не задан обязательный квалификатор. Сервер
останавливается.

Действия пользователя: Задайте его.

### NOSERVER

```
no MSCPHUB server runs on this host'text'
```

Важность: ошибка.

Пояснение: MHMON не нашёл статистику сервера или сервер её не
обновляет — при запуске MHMON четверть секунды следит за ней. На этом
компьютере сервер не запущен, или запущен не тот, что назван в /NODE,
или он завис, или MHMON запущен не от root. С /RECORD MHMON ждёт
сервер.

Действия пользователя: Запустите сервер (systemctl start mscphub);
проверьте /NODE.

### NOSTAT

```
no statistics for MHMON: 'call' failed, errno='n' ('text')
```

Важность: предупреждение.

Пояснение: Сервер не может создать блок статистики в общей памяти
(/dev/shm). Диски он обслуживает, но MHMON и /MODBUS ничего не видят.

Действия пользователя: Проверьте, что /dev/shm есть и не переполнен
(df /dev/shm).

### NOTOPIC

```
sorry, no documentation on 'topic'
```

Важность: ошибка.

Пояснение: /HELP назвал тему, которой нет в библиотеке помощи.

Действия пользователя: Дайте mscphub /HELP, чтобы увидеть список тем.

### RECORD

```
recording every 'n' second(s) to 'file'
```

Важность: информационное.

Пояснение: MHMON начал файл /RECORD.

Действия пользователя: Не требуются.

### SHUTDOWN

```
signal 'n' received, the server is stopping
```

Важность: информационное.

Пояснение: Сервер получил SIGINT или SIGTERM. Он шлёт HOSTSHUT по
каждому открытому виртуальному каналу и, если уже объявил себя, BYE
группе: узлы OpenVMS сразу закрывают виртуальные каналы и каналы к
нему.

Действия пользователя: Не нужны.

### STARTUP

```
MSCPHUB 'ident', node 'name', system ID 'n', group 'n', on 'interface' ('address')
```

Важность: информационное.

Пояснение: Сервер запущен.

Действия пользователя: Не нужны.

### STATS

```
rx 'n' frame(s) ('n' CC, 'n' TR, 'n' dropped, 'n' own, 'n' bad password), tx 'n' frame(s), 'n' error(s)
```

Важность: информационное.

Пояснение: Пишется по SIGUSR1 после NODESTATS: принятые и переданные
кадры, ошибки передачи. Отброшенные -- кадры других групп или для
других узлов; это нормально.

Действия пользователя: Не нужны.

### STATVERS

```
the statistics of 'name' are of version 'n', MHMON reads version 'n'
```

Важность: ошибка.

Пояснение: Сервер и MHMON разных версий, и устройство статистики между
ними изменилось.

Действия пользователя: Пользуйтесь MHMON, установленным вместе с
сервером; ставьте оба из одного комплекта.

### SYSERR

```
'call' failed, errno='n' ('text')
```

Важность: фатальное.

Пояснение: Не удался системный вызов Linux. Сервер останавливается.
Чаще всего:

```
socket(AF_PACKET), errno=1      the server is not run as root (CAP_NET_RAW)
ioctl(SIOCGIFINDEX), errno=19   there is no such interface
```

Действия пользователя: Исправьте то, на что указывают вызов и errno.

### TRSTATS

```
transport: 'n' packet(s) sent, 'n' retransmitted, 'n' received, 'n' duplicate(s), 'n' out of order, 'n' of an old channel; window up to 'n'
```

Важность: информационное.

Пояснение: Пишется по SIGUSR1 после STATS: пакетов передано,
повторено, принято, дубликатов, не по порядку, пакетов старого
канала и самое широкое окно передачи.

Действия пользователя: Не нужны. Немного повторов -- это нормально;
много "out of order" значит, что теряются кадры от узлов (см.
Troubleshooting).

### UNITCFG

```
unit 'name' is 'path', 'n' block(s)'attributes', SLUN 'xxxx'
```

Важность: информационное.

Пояснение: При старте, для каждого диска: его имя на узлах OpenVMS,
его файл или устройство, размер, вид, сектор и носитель, номер юнита
MSCP.

Действия пользователя: Не нужны.

### UNITSTATS

```
unit 'name': ONLINE to 'n' host(s), 'n' command(s) running, 'n' waiting, 'n' read(s) ('n' octets), 'n' write(s) ('n' octets)
```

Важность: информационное.

Пояснение: Пишется по SIGUSR1 для каждого диска после MSCPSTATS: для
скольких узлов диск в состоянии ONLINE (смонтирован или монтируется),
сколько команд на нём выполняется и сколько ждут очереди, сколько
сделано чтений и записей.

Действия пользователя: Не нужны.

### UNSAFE

```
/SYNC=NONE: a WRITE is answered before its data is on disk - for tests only
```

Важность: предупреждение.

Пояснение: Задан /UNSAFE или /SYNC=NONE.

Действия пользователя: Не используйте это с нужными данными.

### UPTIME

```
MSCPHUB 'ident', node 'name', up 'n' day(s) 'hh':'mm':'ss', OpenVMS time of 'zone'
```

Важность: информационное.

Пояснение: Первое сообщение по SIGUSR1: версия, имя сервера, сколько
он работает и пояс /TIMEZONE.

Действия пользователя: Не нужны.

### VCCLOSE

```
virtual circuit to node 'name' ('systemid') is closed: 'reason'
```

Важность: предупреждение.

Пояснение: Виртуальный канал к узлу закрыт. Причина -- одна из:

```
the channel is closed ...                        see CHCLOSE
restarted by the node (START on the open path)   the node rebooted
HOSTSHUT received, the node is shutting down
no acknowledgement after 30 retransmissions      frames are lost
a block transfer the server does not take
the server is stopping
```

После сбоя сервер сразу перезапускает канал, и узел снова открывает
виртуальный канал через несколько секунд.

Действия пользователя: Не нужны, если виртуальный канал открылся
снова. Если он закрывается раз за разом, см. Troubleshooting.

### VCOPEN

```
virtual circuit to node 'name' ('systemid') is open: 'software' 'version' on 'hardware', datagram 'n', message 'n'
```

Важность: информационное.

Пояснение: Узел ответил серверу, и SHOW CLUSTER на нём теперь
показывает сервер. В сообщении то, что узел сообщил о себе:
программа, версия и оборудование, наибольшие датаграмма и сообщение.

Действия пользователя: Не нужны.
