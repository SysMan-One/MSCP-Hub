# MSCPHUB -- MSCP-сервер дисков для узлов OpenVMS

MSCPHUB работает под Linux и даёт узлам OpenVMS в той же локальной
сети пользоваться файлами и дисками Linux как своими дисками. Для
узла OpenVMS он выглядит как контроллер дисков (вроде HSC): узел видит
диски в SHOW DEVICE и монтирует их командой MOUNT.

MSCPHUB говорит по Ethernet на NISCA -- протоколе PEDRIVER. Он не
член VMScluster и не имеет голосов. На узлах OpenVMS ничего менять не
нужно.

Формат:

```
mscphub /CONFIG=файл
mscphub /INTERFACE=if /NODE=имя /SYSTEMID=n /GROUP=n /AUTHORIZE=hex [/квалификаторы]
```

Параметр можно дать в командной строке или в файле /CONFIG. Вместо
/ИМЯ=значение можно писать --ИМЯ=значение.

Это версия X01-09, первый выпуск (v1). Сервер объявляет себя в сети и
проверяет, что его имя и системный номер никем не заняты. Он
открывает канал и виртуальный канал (VC) к каждому узлу OpenVMS
группы; SHOW CLUSTER на узле показывает сервер. Диски /UNIT0 ...
/UNIT7 появляются на узле в SHOW DEVICE. Узел может их
инициализировать (INITIALIZE) и смонтировать (MOUNT), читать и писать:
COPY, BACKUP, ANALYZE/DISK_STRUCTURE работают как с локальным диском.
Один диск могут смонтировать несколько узлов: MOUNT/CLUSTER.

На WRITE сервер отвечает только тогда, когда данные уже на диске
Linux-машины (fdatasync). OpenVMS никогда не просит диск сбросить
кэш, поэтому иначе нельзя. /UNSAFE отключает это для испытаний.

## /CONFIG -- взять параметры из файла

```
/CONFIG=файл
```

В файле по одному параметру в строке, как в командной строке. Строка,
начинающаяся с !, -- комментарий:

```
! MSCPHUB нашего кластера
/INTERFACE=mh0
/NODE=MHUB
/SYSTEMID=65200
/GROUP=4242
/AUTHORIZE=5A3C9E1700000000
```

## /INTERFACE -- сетевой интерфейс

```
/INTERFACE=имя
```

Интерфейс Linux, в сети которого узлы OpenVMS: eth1 или tap в мосту.
Обязателен. Нужны права CAP_NET_RAW (запуск от root). MAC-адрес
интерфейса не меняется.

## /NODE -- SCSNODE сервера

```
/NODE=имя
```

Имя узла, которое увидят узлы OpenVMS: 1-6 символов A-Z, 0-9, $ и _.
Обязателен. Не должен совпадать с именем другого узла группы.

## /SYSTEMID -- SCSSYSTEMID сервера

```
/SYSTEMID=число
```

SCSSYSTEMID, 1-65535. Обязателен. Должен отличаться от SCSSYSTEMID
всех узлов группы: NISCA различает узлы только по младшим 16 битам.

## /GROUP -- номер группы кластера

```
/GROUP=число
```

Номер группы кластера узлов OpenVMS, 1-65279. Обязателен. На OpenVMS
лежит в SYS$SYSTEM:CLUSTER_AUTHORIZE.DAT.

## /AUTHORIZE -- пароль кластера

```
/AUTHORIZE=16 шестнадцатеричных цифр
```

Пароль кластера в виде 8-байтового хэша из CLUSTER_AUTHORIZE.DAT.
Обязателен. Посмотреть его на узле OpenVMS:

```
$ DUMP SYS$SYSTEM:CLUSTER_AUTHORIZE.DAT
```

Хэш -- квадрослово по смещению 8, записанное побайтно: длинное слово
8EF54F24 записывается как 5A3C9E1700000000.

## /LISTEN -- секунды тишины при старте

```
/LISTEN=секунды     (по умолчанию 4)
```

Прежде чем что-то послать, сервер столько секунд слушает сеть и
узнаёт узлы по их HELLO. Если имя или системный номер сервера заняты,
сервер останавливается.

## /ALLOCLASS -- allocation class дисков

```
/ALLOCLASS=число     (по умолчанию 0)
```

Allocation class сервера, 0-255. При /ALLOCLASS=42 узлы OpenVMS
называют диск DKA100 сервера $42$DKA100, при 0 -- MHUB$DKA100 (по
SCSNODE сервера). Не меняйте его, пока узлы пользуются дисками. Не
давайте класс, который узлы кластера уже дают дискам с теми же
именами.

## /UNIT0 ... /UNIT7 -- диски

```
/UNIT0=имя,путь[,RO][,MEDIA=носитель][,SECTOR=байт]
```

Диск, который раздаёт сервер. Имя -- DKcn: DK, буква контроллера A-Z
и номер 0-9999, например DKA100. Путь -- это:

- файл Linux (образ, разрежённый или нет). Его размер при старте в
  блоках по 512 байт -- размер диска. Сервер забирает файл себе
  (flock): второй сервер раздавать его не сможет.
- блочное устройство: диск, раздел, том LVM, loop-устройство, LUN
  iSCSI. Сервер открывает его с O_DIRECT и O_EXCL: устройство,
  смонтированное на Linux-машине или занятое другим сервером, он не
  возьмёт (DEVBUSY). Устройство с сектором 4096 байт работает: запись
  не целыми секторами идёт как чтение-изменение-запись. О разделе,
  который начинается не на границе физического сектора, сервер
  предупреждает (MISALIGN).

  OpenVMS пишет блоками по 512 байт и о секторах 4096 байт не знает.
  Чтобы большая часть записей шла целыми секторами, инициализируйте
  диск с кластером 8 или кратным 8: INITIALIZE/CLUSTER=16 $42$DKA100:
  DATA1. На диске больше 50000 блоков OpenVMS так делает сама, на
  меньшем берёт 1. Записи одного блока (заголовки файлов, битовая
  карта, каталоги) остаются чтением-изменением-записью -- как и в
  диске 4096 байт с эмуляцией 512.

Параметры, в любом порядке:

- RO -- только чтение. Узел монтирует диск с защитой от записи.
- MEDIA=носитель -- кем диск представляется узлу: две или три буквы и
  число, например RZ29 или RRD42. По умолчанию RZ29, а с RO -- RRD42
  (CD-ROM).
- SECTOR=байт -- считать файл диском с сектором 512, 1024, 2048 или
  4096 байт. Только для проверки 4K-дисков; блочное устройство само
  сообщает свой сектор.

Примеры:

```
/ALLOCLASS=42
/UNIT0=DKA100,/srv/vms/data1.img
/UNIT1=DKA200,/dev/vg0/vmsdata
/UNIT2=DKA300,/srv/iso/axpvms083.iso,RO
```

Образ CD OpenVMS (ISO-файл с сектором 2048 байт) раздаётся как есть:
узел монтирует его MOUNT, это RRD42. Не меняйте файл или устройство,
пока сервер их раздаёт.

Дисковый ввод-вывод сервер делает через io_uring. Нужно ядро Linux не
старше пяти лет (5.10 и новее); если io_uring выключен (sysctl
kernel.io_uring_disabled), сервер при старте останавливается с SYSERR.

## /SYNC -- когда WRITE считается записанным

```
/SYNC=DSYNC | GROUP | NONE     (по умолчанию DSYNC)
```

OpenVMS никогда не просит диск сбросить кэш, поэтому сервер отвечает
на WRITE только тогда, когда данные на диске Linux-машины.

- DSYNC -- каждая запись идёт на диск сама по себе (RWF_DSYNC).
- GROUP -- записи, закончившиеся, пока диск сбрасывает кэш, ждут
  следующего сброса и получают ответ вместе: сбросов меньше, когда
  записей много сразу. Так же надёжно, как DSYNC.
- NONE -- то же, что /UNSAFE.

## /CREDITS -- сколько команд узел может прислать сразу

```
/CREDITS=число     (по умолчанию 16)
```

Сколько команд каждый узел OpenVMS может одновременно держать в
работе у дискового сервера, 2-64. Дисковый сервер OpenVMS даёт 32
(MSCP_CREDITS). Больше -- занятый узел держит больше чтений и записей
сразу; число выдаётся при подключении узла.

## /ACK -- когда сервер подтверждает отдельно

```
/ACK=HOLD | FLUSH     (по умолчанию HOLD)
```

Каждый пакет узла нужно подтвердить. Обычно подтверждение едет в
пакете сервера -- в ответе на команду, в данных READ. Когда серверу
нечего послать, он шлёт подтверждение отдельно, коротким пакетом.

- FLUSH -- короткий пакет уходит, как только сервер забрал все
  пришедшие кадры.
- HOLD -- короткий пакет уходит, только когда узел просит
  подтвердить сразу, после 4 пакетов или самое позднее через 20 мс.
  В остальных случаях подтверждение ждёт ответа сервера. Узлу
  приходится принимать меньше пакетов.

HOLD шлёт намного меньше пакетов и немного быстрее. FLUSH -- прежний
режим; сравнить их помогут счётчики SIGUSR1 (ACKSTATS, LATSTATS).

## /TIMEZONE -- часовой пояс времени для узлов

```
/TIMEZONE=LOCAL | UTC | [+|-]чч[:мм]     (по умолчанию LOCAL)
```

Узел OpenVMS живёт по местному времени. Сервер сообщает узлам своё
время, когда открывает виртуальный канал; SHOW CLUSTER и SCACP
показывают его как время запуска сервера. LOCAL -- пояс Linux-машины
(TZ, /etc/localtime), вместе с летним временем. Если узлы живут в
другом поясе, дайте смещение, например /TIMEZONE=+03:00. Это видит
только оператор, протокол работает с любым поясом.

## /UNSAFE -- отвечать на WRITE до записи на диск

Сервер отвечает на запись, как только данные у Linux в страничном
кэше. Так быстрее, но при сбое или пропадании питания Linux-машины
пропадут данные, которые узел OpenVMS считает записанными. Только для
испытаний. При старте сервер выводит UNSAFE.

## /PASSIVE -- ничего не передавать

Сервер только слушает и сообщает об увиденных узлах. Каналов не
открывает и ничего не передаёт. Безопасно в любой сети, например
чтобы посмотреть на рабочий кластер.

## /TRACE -- писать в журнал каждый кадр

Каждый принятый кадр записывается в журнал, как и каждый шаг
каждого канала.

## /LOGFILE -- файл журнала

```
/LOGFILE=файл
```

Сообщения идут в этот файл; без /LOGFILE -- в стандартный поток
ошибок.

## /HELP -- показать это описание

```
/HELP
/HELP="тема подтема"
```

Примеры:

```
$ mscphub /HELP=/SYSTEMID
$ mscphub "/HELP=Messages IDCLASH"
```

## Signals -- сигналы

```
SIGINT, SIGTERM    остановить сервер
SIGUSR1            записать в журнал, чем сервер занят: UPTIME, NODESTATS
                   для каждого узла, затем счётчики (STATS, TRSTATS,
                   ACKSTATS, BLKSTATS, MSCPSTATS, UNITSTATS, BKSTATS,
                   LATSTATS)
```

Под systemd:

```
# systemctl kill -s USR1 mscphub
# journalctl -u mscphub -n 30
```

## Service -- сервер как служба systemd

Установка кладёт юнит mscphub.service, но не включает его: сервер,
запущенный сам по себе, начинает разговаривать с кластером в своей
сети. Юнит читает /etc/opt/mscphub/mscphub.conf и без него не
запускается.

```
# cp /etc/opt/mscphub/mscphub.conf.example /etc/opt/mscphub/mscphub.conf
# vi /etc/opt/mscphub/mscphub.conf
# systemctl enable --now mscphub
# journalctl -u mscphub -f
```

Чтобы привязать сервер к процессору или дать ему другие параметры,
используйте drop-in (systemctl edit mscphub), сам юнит не правьте.

## Troubleshooting -- что проверить первым делом

Сервер сразу останавливается. Прочтите последнее сообщение: оно с
буквой F (фатальное) и объясняет причину. См. тему Messages.

Не видно ни одного узла: ANNOUNCE сообщает 0 узлов. Проверьте
/GROUP. Проверьте, что интерфейс поднят и стоит в нужном мосту или
VLAN. На OpenVMS проверьте, что PEDRIVER работает: MCR SCACP SHOW
CHANNEL. Посмотрите на провод:

```
# tcpdump -i mh0 ether proto 0x6007
```

Узлы видны, но CHOPEN нет. Поищите AUTHFAIL: хэш пароля в
/AUTHORIZE не тот, что у группы. Проверьте, что не задан /PASSIVE. На
OpenVMS канал к серверу и его состояние покажет MCR SCACP SHOW
CHANNEL.

Канал открывается и снова закрывается (CHOPEN, потом CHCLOSE).
Причина написана в CHCLOSE. «nothing heard from the node» значит, что
кадры теряются между узлом и сервером: проверьте мост или VLAN.

Канал открыт, но VCOPEN нет. Узел OpenVMS шлёт START по открытому
каналу каждые 5 секунд. Запустите сервер с /TRACE и поищите «PPD
START»: если он есть, посмотрите предупреждение после него.

VC открыт, но дисков на узле нет. Поищите CONOPEN: узел соединяется
с MSCP$DISK через несколько секунд после открытия VC. Нет CONOPEN --
проверьте, что заданы /UNITn (UNITCFG при старте). На OpenVMS
проверьте, что работает процесс CONFIGURE (SHOW SYSTEM): он грузит
драйвер класса DUDRIVER.

VC открывается и снова закрывается. Причина написана в VCCLOSE.
Посмотрите счётчики (SIGUSR1, сообщение TRSTATS): много повторов
значит, что кадры теряются.

MOUNT или COPY на узле кончается ошибкой ввода-вывода. Поищите IOERR:
файл на Linux не удалось прочитать или записать (например, кончилось
место). Поищите также MSCPERR и BLKERR.

Запись идёт очень медленно, а чтение нет. Теряются кадры от узла к
серверу: потерянный кадр узел повторяет только через секунду и больше.
Проверьте мост, VLAN, кабели. Посмотрите TRSTATS: много пакетов «не по
порядку» -- это потери кадров от узла.

## Messages -- сообщения сервера

Каждое сообщение в форме OpenVMS:

```
%MSCPHUB-F-IDCLASH, node ALPHA1 (08-00-2B-E5-40-01) uses the system ID low word 65534 of this server
```

Буква после MSCPHUB -- важность: S успех, I информация, W
предупреждение, E ошибка, F фатальная (сервер останавливается).

### STARTUP

Сервер запущен: версия, имя, системный номер, группа, интерфейс.
Ничего делать не нужно.

### LISTEN

Сервер слушает сеть перед тем, как объявить себя. Ничего делать не
нужно.

### ANNOUNCE

Время тишины вышло, сервер шлёт HELLO. Показано, сколько других узлов
он увидел. С /PASSIVE сказано "listens only", и сервер ничего не шлёт.
Ничего делать не нужно.

### NEWNODE

Сервер впервые увидел узел: имя, системный номер, адаптер, версия
NISCA. Ничего делать не нужно.

### IDCLASH

Другой узел использует те же младшие 16 бит SCSSYSTEMID, что и
сервер (same low 16 bits). Такие узлы в сети не различить. Сервер
останавливается, ничего не передав.

Что делать: дайте серверу другой /SYSTEMID. На OpenVMS занятые номера
покажут SHOW CLUSTER или MCR SYSGEN SHOW SCSSYSTEMID.

### NAMECLASH

У другого узла тот же SCSNODE, что у сервера. Сервер
останавливается, ничего не передав.

Что делать: дайте серверу другой /NODE.

### NOPARAM

Не задан обязательный параметр. Что делать: задайте его.

### IVPARAM

Неверное значение параметра; в сообщении сказано, какое ожидается.
Что делать: исправьте значение.

### SYSERR

Не удался системный вызов Linux; показаны вызов и errno. Чаще всего:

```
socket(AF_PACKET), errno=1      запускайте сервер от root (CAP_NET_RAW)
ioctl(SIOCGIFINDEX), errno=19   нет такого интерфейса
```

### MANYNODES

Узлов в сети больше, чем помнит сервер (64); лишний узел на
совпадение не проверяется. Что делать: сообщите разработчикам.

### CHOPEN

Канал к узлу открыт: рукопожатие закончено. Показаны версия CC узла,
его pipe quota, размер буфера и сервисы (предлагает/требует). Ничего
делать не нужно.

### CHCLOSE

Канал к узлу закрыт. Причина в сообщении:

```
BYE received, the node is going down    узел останавливается или упал
restarted by the node                   узел начал канал заново
no answer to the handshake in 5 seconds нет ответа на рукопожатие
nothing heard from the node for 8 seconds  8 с ни одного кадра от узла
the node has changed its name or system ID узел сменил имя или номер
the server is stopping                  сервер останавливается
```

Работающий узел снова откроет канал через несколько секунд. Что
делать: ничего, если канал открылся снова. Если нет -- см.
Troubleshooting.

### AUTHFAIL

Узел прислал сообщение CC с неверным паролем кластера. Сообщение
отброшено, канал к этому узлу не открывается. Сообщается по одному
разу на узел.

Что делать: задайте в /AUTHORIZE хэш группы этого узла (см.
/AUTHORIZE). Проверьте и /GROUP.

### VCOPEN

Виртуальный канал к узлу открыт: узел ответил на наш STACK. Показано,
что узел сообщил о себе: программа, версия, оборудование, наибольшие
датаграмма и сообщение. Теперь SHOW CLUSTER на этом узле показывает
сервер. Ничего делать не нужно.

### VCCLOSE

Виртуальный канал к узлу закрыт. Причина в сообщении:

```
the channel is closed ...                    см. CHCLOSE
restarted by the node (START on the open path)   узел перезагрузился
HOSTSHUT received, the node is shutting down     узел останавливается
no acknowledgement after 30 retransmissions  кадры теряются
a block transfer the server does not take    блочная передача, которой сервер не ждёт
the server is stopping                       сервер останавливается
```

После сбоя сервер сразу перезапускает канал, и узел снова открывает
VC через несколько секунд. Что делать: ничего, если VC открылся
снова. Если он закрывается раз за разом -- см. Troubleshooting.

### TRSTATS

Счётчики транспорта, пишутся после STATS: пакетов передано,
повторено, принято, дубликатов, не по порядку, пакетов старого
канала и самое широкое окно передачи. Немного повторов -- это
нормально. Ничего делать не нужно.

### ACKSTATS

Подтверждения, пишутся после TRSTATS: режим /ACK, сколько пакетов
узлов просили подтвердить сразу, сколько подтверждений уехало в
пакетах сервера и сколько ушло отдельно -- по просьбе узла, на
пришедший дважды пакет, на пачку пакетов (/ACK=HOLD), когда все
кадры забраны (/ACK=FLUSH), по такту 20 мс. Чем меньше отдельных,
тем лучше. Ничего делать не нужно.

### BLKSTATS

Счётчики данных, пишутся после TRSTATS: кусков данных отправлено
узлам (READ) и сколько в них байт, сколько RET_CNF узлы прислали в
ответ, сколько REQ_DAT отправил сервер (WRITE), кусков данных принято
и сколько в них байт, кусков отброшено. Ничего делать не нужно.

### MSCPSTATS

Состояние дискового сервера, пишется после BLKSTATS: сколько команд
узлов сейчас в работе и сколько байт буферов данных они держат.
Когда дисками никто не пользуется, оба числа 0. Если число больше 0
и не уменьшается, хотя ни один узел не подключён, это ошибка
сервера: сообщите о ней и приложите журнал. Иначе ничего делать не
нужно.

### UNITSTATS

По одному на каждый диск, пишется после MSCPSTATS: для скольких
узлов диск в состоянии ONLINE (смонтирован или монтируется), сколько
команд на нём выполняется сейчас и сколько ждут очереди, сколько
сделано чтений и записей и сколько в них байт. Если ни один узел не
подключён, «выполняется» и «ждут» равны 0. Ничего делать не нужно.

### UNITCFG

При старте: диск, который раздаёт сервер, его имя на узлах OpenVMS
($42$DKA100, или MHUB$DKA100 при /ALLOCLASS=0), файл, размер и номер юнита MSCP. Ничего делать не нужно.

### CONOPEN

Узел OpenVMS соединился с сервером дисков (MSCP$DISK): его драйвер
класса VMS$DISK_CL_DRVR. Показаны кредиты обеих сторон. Ничего
делать не нужно.

### CONCLOSE

Соединение с сервером дисков закрыто: узел отключился, его VC
закрылся или сервер разорвал соединение сам. Что делать: ничего,
узел соединится снова. Если причина -- «an end message was held
back», см. MSCPERR.

### MSCPERR

Сервер собирался отправить ответ, от которого узел OpenVMS упал бы
(BUG_CHECK его драйвера класса). Он его не отправил и разорвал
соединение. Это ошибка сервера. Что делать: сообщите о ней,
приложив журнал /TRACE.

### IOERR

Файл диска на Linux не удалось прочитать или записать: в сообщении
команда, диск, блок, размер и ошибка Linux. Узел OpenVMS получает
ошибку привода. Что делать: проверьте файловую систему Linux-машины --
«No space left on device» значит, что файл разреженный, а место на
файловой системе кончилось.

### BLKERR

От узла пришёл кусок данных, которого не ждёт ни одна команда:
команда уже кончилась или узел прислал его дважды. Сервер его
отбрасывает. Что делать: ничего, если это редко. Если часто --
сообщите, приложив журнал с /TRACE.

### UNSAFE

Задан /UNSAFE или /SYNC=NONE: на WRITE сервер отвечает до записи на
диск. Что делать: не используйте это с нужными данными.

### BKSTATS

По одному на каждый диск, пишется после его UNITSTATS: сектор диска,
сколько записей прошло как чтение-изменение-запись (сектор 4096
байт), сколько секторов они сначала прочитали и сколько из них было
среди последних 2, 16, 128 и 512 записанных секторов (столько сберёг
бы кэш такого размера), сколько записей ждали другую запись в те же секторы, и при
/SYNC=GROUP -- сколько сбросов кэша покрыли сколько записей. Ничего
делать не нужно.

### LATSTATS

По одному на каждый диск и на каждую из команд READ и WRITE,
пишется после его BKSTATS, если такие команды были: сколько их,
среднее время от команды до ответа в микросекундах и какая часть
его пришлась на диск Linux (backend), на данные по сети
(transfers) и на остальное (ожидание очереди диска, сам сервер).
Дальше самое долгое время и сколько команд заняли меньше 0,1, 0,3,
1, 3 и 10 мс и дольше. Счётчики идут с запуска сервера: чтобы
измерить тест, пошлите SIGUSR1 до и после него и вычтите. Ничего
делать не нужно.

### IOSTUCK

Команда уже 15 секунд в диске Linux. Сервер отменяет её; если отмена
прошла, узел получает ошибку устройства. Если нет (Linux ещё пишет),
диск ждёт её. Что делать: проверьте диск Linux под юнитом -- умерший
диск, пропавший сервер iSCSI или NFS. Смотрите dmesg.

### DEVBUSY

Сервер не может забрать себе блочное устройство из /UNITn: оно
смонтировано на Linux-машине, занято LVM или RAID, или его держит
другой сервер. Сервер останавливается. Что делать: отмонтируйте его
или дайте другое устройство. Никогда не раздавайте устройство, которым
пользуется сама Linux-машина.

### MISALIGN

Блочное устройство из /UNITn -- чаще всего раздел -- начинается не на
границе физического сектора диска Linux, а на столько-то байт внутри
него. Тогда ни одна запись узла не ложится целыми секторами, и каждая
идёт как чтение-изменение-запись, в сервере или в самом диске. Сервер
всё равно раздаёт устройство. Что делать: для нового диска сделайте
раздел с началом, кратным 1 МБ (parted и fdisk так делают по
умолчанию), и перенесите данные.

### UPTIME

Первое сообщение по SIGUSR1: версия, имя сервера, сколько он
работает и пояс /TIMEZONE. Действий не нужно.

### NODESTATS

По одному на каждый известный серверу узел, после UPTIME: состояние
канала и сколько раз он открывался, состояние виртуального канала и
сколько раз он открывался, сколько соединений SCS открыто сейчас.
Дважды "OPEN" и одно соединение -- узел, который работает с дисками.
Растущее число открытий значит, что узел то пропадает, то
появляется: смотрите CHCLOSE и VCCLOSE в журнале. Иначе действий не
нужно.

### SHUTDOWN

Сервер получил SIGINT или SIGTERM и останавливается. Он шлёт HOSTSHUT
по каждому открытому VC, затем, если уже объявил себя, -- BYE группе:
узлы OpenVMS сразу закрывают VC и каналы к нему. Ничего делать не
нужно.

### STATS

Счётчики: принято кадров (CC, TR, отброшено, свои, с неверным
паролем) и передано, ошибки передачи. Отброшенные -- кадры других групп и других узлов, это
нормально.

### NOTOPIC

/HELP назвал тему, которой нет в библиотеке.
